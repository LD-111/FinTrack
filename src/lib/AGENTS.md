# lib

- `types.ts` — `Account`, `Transaction`, `Category`, `Budget`, `MerchantMemory`, `AppSettings`, `ValuationLog`, `PortfolioSnapshot`. Amounts are cents. `AccountType` includes `investment` | `crypto` | `stock`. `Transaction.kind` is `expense` | `income` | `transfer` | `refund`. Amounts stay positive; `refund` is money back into a spending category.
- `accounts.ts` — slug + `#token` matching (exact, then unique prefix; active accounts only), `matchArchivedAccountToken` for the same match on archived accounts, `matchAccountsByName` (exact, prefix, then substring), `planAccountDeletion` (rows to remove and other accounts' balance deltas when transfers are deleted), `suggestTransferDestination` (same amount, then most recent, then the only other active account), transfer labels, `isPortfolioAccount`.
- `db.ts` — Dexie v3 stores: accounts, categories, transactions, budgets, merchantMemory, settings, valuationLogs. Bump the version when the schema changes. v2 upgrade seeds Cash, backfills `accountId`, adds `cat_transfer`. v3 adds `valuationLogs`. Never create these stores with raw `indexedDB.open` — Dexie must own the schema or hydrate throws `BulkError` and the UI stays on the splash.
- `seed.ts` — first-launch categories + Cash account + USD/en-US settings. Stable ids such as `cat_food`, `cat_uncategorized`, `cat_transfer`, `acct_cash`. `seedIfEmpty()` no-ops once any category exists; leftover IndexedDB is not reset on later visits.
- `parser.ts` — `[+]amount [description] [@category] [#account] [date-hint]`. Transfers: `amount #from -> #to` or `transfer 500 from #a to #b`. `amount #from` with no description, and `amount #from #to` with no description, are transfers; a description word stays an expense, and a leading `+` is money in (`income` until category resolution). Accepts `12.50` and `12,50`. When a category list is passed, `@` consumes following words that complete a longer exact category name (`@Other income`).
- `categorizer.ts` — explicit `@token` → merchant memory → fuzzy → Uncategorized. Category prefixes must be unique, same as accounts. Fuzzy memory requires a shared prefix of at least 3 characters at the start of a key or at a word boundary. `kindForMoneyIn` turns money-in on a spending category into `refund` (not Uncategorized, not archived, not an income category). `kindAfterCategoryChange` keeps cash direction when the category changes.
- `derived.ts` — month totals skip transfers. Income adds to income. A refund subtracts from spent and from that category, and is omitted from income. `accountBalances` = opening + income + refunds − expenses ± transfers (book value).
- `portfolio.ts` — principal (opening + transfers in, reduced on the way out by the share of market value withdrawn; a full withdrawal leaves principal at the remaining value, so an emptied account shows no profit and the next deposit starts a new return), current value (last log + later transfers, income, and refunds − later expenses), TWR, chart series. Fees and dividends do not change principal. Do not store these on `Account`. `portfolioViews` walks each account once and returns the snapshot and the series together.
- `wealth.ts` — total of liquid book value (bank, cash, savings) and portfolio market value, pie slices (positive balances only), and a month-end series. The UI labels the liquid side Liquid. Derived, not stored. Archived accounts are omitted unless requested, and that choice applies to every month. The current month’s point is the live total, so it matches the accounts sum. Portfolio points come from the existing series.
- `money.ts` / `dates.ts` — display and parse helpers. Dates stay local calendar dates. `formatSignedMoney` treats transfer as unsigned and a refund as a positive amount.
- `shell.ts` — `isCaptureShell(platform, search, dev)` is true for `android` and `ios`, and for `?capture=1` only when `dev` is true. `isNativeMobile()` reads `@tauri-apps/plugin-os` inside a Tauri webview.
- `workbookFile.ts` — save and open for the xlsx inside Tauri. `saveWorkbookFile` returns the written path, or null when the dialog is cancelled. The dialog adds the chosen path to the fs scope for that session. The browser shell still uses `downloadWorkbook` in `excel.ts`.
- `excel.ts` — SheetJS workbook. Export downloads `fintrack-YYYY-MM-DD.xlsx` (Accounts, Categories, Transactions, Budgets, Valuations). Amounts are decimal currency; dates are `YYYY-MM-DD`. Import plans inserts only: skip existing ids, match an account or category by id then name (accounts also by slug), and create an unknown name (account type `bank`, category kind from the transaction, budgets are expense). `kind: "refund"` round-trips; an imported `income` or `refund` on a spending category is stored as `refund`. Empty account uses the default account. Empty category uses Uncategorized, or Transfer for a transfer. A category that already has a budget is left unchanged. `planSessionImport` runs that same planner on a ledger snapshot.
- `handoff.ts` — session URL (`/v1/handoff` plus a 32-hex token), snapshot parsing, the confirm copy, and which host accounts and categories the guest does not already have by id. Merchant memory is not in the snapshot. `handoffClient.ts` posts it: the Tauri command on a phone, `fetch` from a browser capture tab.
- `toast.ts` — lightweight toast bus used by FinanceContext undo/delete.
